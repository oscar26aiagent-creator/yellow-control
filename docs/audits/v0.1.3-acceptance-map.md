## Milestone acceptance checkpoints

### Content architecture gates

- one concept per file
- no oversized mixed-topic governance dumps
- role-based reader entry path from docs/index.md
- architecture represented in docs/architecture.md with required Mermaid diagrams

### Public-safety gates

- no private source repository content copied verbatim
- no credentials, tokens, runtime secrets, session artifacts, or private logs
- no private hostnames or private IP data
- no private register entries
- examples are fictional and clearly labeled

### Formatting and readability gates

- valid markdown headings and tables
- Mermaid uses fenced syntax blocks
- internal links resolve
- SKILL.md contains exactly one YAML frontmatter block
- YAML examples parse

### Governance and skill alignment gates

- README is clear about scope and non-endorsement status
- docs/hermes/* contains usage and submission-readiness guidance
- SKILL.md aligns with Hermes skill authoring expectations
- progressive disclosure enforced: concise SKILL, deeper docs in docs/ and references/
