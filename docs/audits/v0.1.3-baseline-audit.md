## Findings

### 1) README layout problems

Observed:
- README status is outdated for this programme and still references v0.1.2.
- README contains wording that should not remain in v0.1.3 candidate status framing.
- README documentation map points to the old monolithic doc set rather than the target split tree.

Impact:
- Entry-point clarity is reduced for maintainers and reviewers.

### 2) Mermaid rendering problems

Observed:
- Mermaid blocks are fenced correctly where present.
- Architecture coverage is incomplete for the target model: no dedicated docs/architecture.md with the required four diagrams.

Impact:
- Current visualization is partial and not aligned with milestone acceptance criteria.

### 3) Markdown table problems

Observed:
- Pipe tables are present and generally syntactically valid.
- Multiple tables mix policy concepts with runtime-specific operational details and historical notes in very large documents.

Impact:
- Readability and reviewer extraction quality are weak despite mostly valid syntax.

### 4) Incoherent or oversized docs

Observed large files:
- docs/policy-gates.md: 2056 lines
- docs/runtime-maintenance-governance.md: 1083 lines
- docs/backup-and-rollback.md: 482 lines
- docs/external-service-governance.md: 480 lines

Assessment:
- Significant mixed-topic accumulation exists.
- Core concepts, runtime specifics, examples, and history are blended in ways that reduce maintainability.

### 5) Missing concept separation

Observed:
- Core concepts are bundled in broad documents instead of isolated concept files.
- Required target concept files (adal, cdel, esal, pcl, policy-gates, backup-and-rollback) are not split into the requested docs/concepts structure.

Impact:
- Harder for sysadmin, cyber-security, and Hermes reviewers to locate authoritative definitions quickly.

### 6) Missing register templates

Observed:
- Target register docs under docs/registers are absent.
- Target sample YAML register files under examples are absent.

Impact:
- No public-safe canonical register templates for onboarding contributors.

### 7) Hermes SKILL.md alignment gaps

Observed:
- SKILL.md has one frontmatter block and valid high-level structure.
- Version is 0.1.2, not target 0.1.3.
- Structure is longer than desired for progressive-disclosure style; deeper operational details should continue moving into docs/references.
- Dedicated docs/hermes/skill-usage.md and docs/hermes/skill-hub-submission-readiness.md are missing.

Impact:
- Not yet aligned with v0.1.3 acceptance scope for concise skill + canonical references layout.

### 8) Bad redaction strings

Observed in current public docs:
- forbidden authority wording variants are present in existing files
- historical strings with disallowed forms are present
- prohibited status phrasing is present in README

Impact:
- Violates hard wording requirements for the rebuild candidate.

### 9) Private-data risk checks

Observed risk pattern:
- Current docs include runtime-specific operational placeholders and service-level detail density that increase accidental leakage risk.
- No direct credential material found during this milestone audit.

Required action:
- Replace or generalize runtime-identifying details with public-safe abstractions.
- Keep all examples explicitly fictional.

### 10) Missing or weak cross-links

Observed:
- No docs/index.md entrypoint with role-based reading paths.
- Cross-link strategy is implicit and spread across README and monolithic docs.

Impact:
- Navigation and reviewer workflow are weaker than required.
